# Current conditions test card

Without an explicit opt-in, default builds do not render the card or request any weather data. A local/approved staging build can opt in at build time with `NEXT_PUBLIC_HDMS_MAP_WEATHER_TEST=1`. Explicit action is required per request. The selected map point is used when present; otherwise the Pattani map center is used. GPS is requested only on a clearly labeled action, approximate coordinates (2 decimals) are sent without a referrer or credentials, and no position is persisted by HDMS. The prototype does not poll. Open-Meteo’s current field represents a model estimate for a recent time, not a station reading. The API timestamp is shown in Asia/Bangkok, not a claim about model initialization or time of a field observation. Observations from [TMD Weather3HoursBySynop](https://data.tmd.go.th/api/doc/reference/Weather3HoursBySynop.pdf) are a separate station product and are not fetched by this prototype.

Before any public enablement, check the latest [Open-Meteo terms](https://open-meteo.com/en/terms) and confirm this institutional use and expected volume qualify or arrange the proper service tier. CC BY 4.0 [data licensing](https://open-meteo.com/en/licence) permits attributed reuse separately from the free API's non-commercial eligibility, published limits, and lack of uptime guarantee. Keep the model label and timestamp; it is not observed rainfall or an official warning. Do not add keys to client code. A production gate should also cover quotas, resilience, and privacy notices.

Fixture verification: `NEXT_PUBLIC_HDMS_MAP_WEATHER_TEST=1 PLAYWRIGHT_STATIC=1 npm run test:e2e:local -- tests/e2e/map-current-weather.spec.ts`. Set `NEXT_PUBLIC_HDMS_MAP_WEATHER_TEST_GPS=1` as well to exercise staging GPS. Repeat with all three flags unset to verify the default build.

Fixture responses are intercepted by Playwright and explicitly identified as **ข้อมูลจำลอง**. Non-fixture responses are labeled **ข้อมูลจากแบบจำลอง**. Pattani read-only requests matching the documented format with the GitHub Pages Origin header returned HTTP 200 and Access-Control-Allow-Origin: *. Chromium requests in this environment had egress/proxy issues; connectivity/reliability in Thailand is not established. Under the free service privacy terms, provider logs may include sent coordinates and are retained up to 90 days. Keep the location disclosure and have HDMS privacy owners approve this before public enablement.

## Conservative public candidate (off unless explicitly enabled)

- `NEXT_PUBLIC_HDMS_MAP_WEATHER_PUBLIC=1` is an independent, build-time public enable switch. Only the fixed public Pattani reference point (6.82°N, 101.25°E), not the map selection or browser location, is used, after pressing **ดูสภาพอากาศ**. No polling, analytics or position persistence is added. Browser requests still connect to the provider and can reveal ordinary network metadata such as the IP address.
- The staging-only GPS exercise requires both `NEXT_PUBLIC_HDMS_MAP_WEATHER_TEST=1` and `NEXT_PUBLIC_HDMS_MAP_WEATHER_TEST_GPS=1`. The GPS option stays unavailable in public mode even if all flags are set. Default builds and public mode never request GPS for this card. The previous Open-Meteo assessment covers the two-decimal coordinates only in that staging exercise.
- Provider terms cite non-profit websites without subscriptions/advertising as eligible examples, but do not explicitly call out deployed government operational services. HDMS has confirmed non-commercial use. Before public enablement, ensure it remains ad-free and non-subscription, the display remains informational (not a warning or travel recommendation), usage satisfies published limits, and a browser on the intended public network can access it. Keep public flag off until those checks pass; disabling the flag and rebuilding rolls the feature back independently.
- Opening the card does not send a request. The model valid time is not model initialization or a field observation. Data more than two hours old or more than ten minutes future, and provider/network failures, are not displayed as current conditions and do not replace traffic/official warnings.
- For candidate browser tests set `NEXT_PUBLIC_HDMS_MAP_WEATHER_PUBLIC=1` instead of the staging flag. This release excludes offline demos and real radar/track overlays.

Public mode keeps successful fixed-point data in browser memory for five minutes and suppresses duplicate fetches while loading. Requests are suppressed for 30 seconds after failure, longer if the provider sends a usable Retry-After on HTTP 429. Failed or expired data are not displayed as current; an already-open result expires quietly without refreshing. This is per-page memory, not a shared quota or uptime guarantee. If aggregate traffic approaches the free limits, use a first-party cache/gateway or disable the flag; do not add a key to the browser or reduce TTL. No scheduled publisher or deployment workflow is changed.

## On-site opt-in check
The public map also accepts `?weather-test=1` on the actual site origin as an explicit test link, without enabling the card for ordinary visits. It offers the fixed Pattani reference and an optional weather action using the existing map ‘ตำแหน่งของฉัน’ control, then an explicit ‘ดูอากาศตามตำแหน่งบนแผนที่’ action. The existing button only finds the location; it does not contact the weather provider. Round GPS to two decimals, disclose third-party transfer before the click, send no credentials/referrer, and never put coordinates in the HDMS URL, telemetry, or stored browser data. GPS does not use or populate the fixed-point cache. Denied GPS makes no hidden fallback call. No option makes an automatic request. Open the test card then separately request the current conditions. If the provider fails, it must show an error without mock values. Strip the query flag to leave test mode immediately. Do not set the general-public build flag until real browser checks and the service limit review pass. No radar or alert status is changed.
