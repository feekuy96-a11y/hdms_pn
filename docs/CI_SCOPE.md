# เส้นทางตรวจ CI ของ HDMS

CI ยังรันทุก PR และ push เข้า `main` และคงชื่อด่าน `verify` เดิม เปลี่ยนเฉพาะชุดงานที่ต้องผ่านตาม diff ไม่ใช้ป้าย PR หรือคำบอกเล่าเป็นเงื่อนไขข้ามเทสต์

| ระดับ | งานที่เข้าเงื่อนไข | ตรวจอะไร |
| --- | --- | --- |
| เอกสาร | เฉพาะไฟล์คู่มือที่อยู่ในรายชื่อของตัวจัดประเภท ไม่รวมเอกสารที่ขั้นสร้างเว็บนำไปใช้ | ช่องว่างใน diff และลิงก์ภายใน repo ที่เพิ่มหรือแก้ในบรรทัดใหม่ |
| ข้อความแสดงผล | แก้เฉพาะค่า plain text ที่อนุญาตใน `config/public-display-copy.json` โดยไม่มีการเปลี่ยนโครงสร้าง อาจมีคู่มือที่อนุญาตร่วมได้ | ลิงก์คู่มือ, lint/type/Pages build, เปิดข้อความและตรวจการแสดงผลบนคอมและมือถือ |
| เต็ม | โค้ด TS/TSX, config, API, CI, คีย์/ชื่อปุ่มหรือ aria, ไฟล์ไม่รู้จัก หรือพิสูจน์ diff ไม่ได้ | สอง browser shards และ offline opt-in/rollback ตามเดิม |

ตัวอย่างข้อความที่เปิดให้ใช้เส้นทางเบารอบนี้คือหัวข้อกรณีไม่มีรายงานน้ำท่วม ข้อความกดปุ่ม ข้อความที่ใช้เป็น selector และคำเตือนการเดินทางไม่อยู่ในไฟล์นี้ ข้อความตัวอย่างเดิมไม่เปลี่ยน การย้ายข้อความใหม่ออกจาก TSX เป็นงานโค้ดเต็มครั้งแรก ห้ามใส่ข้อความที่ใช้คำนวณหรือเป็นสัญญา API ไว้ในไฟล์ข้อความ

งานจัดประเภทใช้ตัวตรวจจาก commit ฐานที่ยืนยันว่าเป็นบรรพบุรุษของรุ่นที่ตรวจ หากเป็นการติดตั้งตัวตรวจครั้งแรก ขาดประวัติ หรือรายการ/รูปแบบไฟล์ไม่ตรง จะตรวจชุดเต็ม กรณีเปลี่ยน workflow หรือตัวจัดประเภทก็เป็นชุดเต็ม

Pages ยังใช้ผล CI สำเร็จจาก push เข้า `main` และสร้างจาก SHA เดิมตาม workflow ปัจจุบัน เอกสารล้วนไม่รันชุดเบราว์เซอร์หรือ build ภายใน CI แต่ Pages ที่เป็น workflow แยกยังคงทำงานตามกติกาเดิม
