# UI_CONTRACT.md — สัญญาด้านหน้าจอ (อ่านก่อนแก้ UI)

## 1. หลักการ
| | หน้าประชาชน `app/page.tsx` | หน้าแอดมิน `app/admin/page.tsx` |
|---|---|---|
| อุปกรณ์หลัก | มือถือ 360–430px (ออกแบบจากมือถือก่อน) | คอมพิวเตอร์ ≥ 1024px (ออกแบบจากเดสก์ท็อปก่อน) |
| งานหลัก | รู้ว่า "ถนนไหนผ่านได้ไหม" และ "ไปทางไหนแทน" ใน 5 วินาที | กรอก/แก้ข้อมูลถูกต้องและเร็ว ไม่พลาด |
| ลำดับข้อมูล | สถานะ → ระดับน้ำ → ทางเลี่ยง → รูป → ประวัติ | หัวข้อ/ขั้นตอน → ช่องกรอก → ปุ่มหลัก |
| พื้นที่กด | ≥ 44×44px | ≥ 40px สูง |
| ตัวอักษรอ่านจริง | ≥ 12px (ตัวหลัก 14px ขึ้นไป) | ≥ 12px (ช่องกรอก 14px) |

ตัวเลือกทั่วไป: ไม่ใช้สีอย่างเดียวบอกสถานะ (ต้องมีไอคอน/ข้อความ), โฟกัสคีย์บอร์ดมองเห็นชัด, รองรับ `prefers-reduced-motion`, ทุกจอมี Loading/Empty/Error/Success

## 2. โทเค็นและส่วนประกอบกลาง
- `app/globals.css`: `.doh-readable` (ยกขนาด `text-[10px]`/`text-[11px]` เป็น 12px + วงโฟกัส) ใส่ที่ราก; `.doh-form` (ช่องกรอก ≥ 40px, 14px, มุมโค้งเท่ากัน, caption ของ label) ใส่ที่พื้นที่ฟอร์มแอดมิน
- `components/admin/ui.tsx`: `FormSection` (การ์ดหัวข้อมีเลขขั้น), `ToolGroup` (กลุ่มปุ่มมีป้าย), `ActionButton` (`primary | secondary | pick | danger`, `active`), `StickyActionBar` (แถบบันทึกลอยติดขอบล่าง)
- สถานะจราจร: ใช้ `getTrafficPresentation` และ `STATUS_*` ใน `app/page.tsx` ชุดเดียว (R1)

## 3. กติกาจัดวางฟอร์มแอดมิน
1. หนึ่งฟอร์ม = หลาย `FormSection` ตามลำดับงานจริง (ข้อมูล → ตำแหน่ง/เส้น → สถานการณ์/ข้อความ) แต่ละการ์ดมีหัวข้อ 1 บรรทัดและคำอธิบายสั้น ไม่เกิน ~7 ช่องต่อการ์ด
2. ปุ่มแบ่ง 3 ระดับ: **หลัก** (หนึ่งปุ่มต่อการ์ด สีเด่น) · **รอง** (กลุ่มด้วย `ToolGroup` ตามหน้าที่) · **อันตราย** (`danger` แยกกลุ่ม และต้องมีขั้นยืนยันถ้าลบข้อมูลถาวร)
3. ปุ่มบันทึก/ยกเลิกของฟอร์มยาวอยู่ใน `StickyActionBar` เสมอ
4. ช่องกรอกทุกช่องมี label ที่เข้าถึงได้ (`<label>` หรือ `aria-label`) ห้ามใช้ placeholder แทน label
5. พื้นที่ฟอร์มรองรับกว้าง ~480–900px: ใช้ `grid-cols-1 sm:grid-cols-2` ไม่ล็อกความกว้างเป็นพิกเซล
6. แถบเครื่องมือเรียงตามความถี่: ปุ่มหลัก → กลุ่มเครื่องมือ → ย้อนกลับ/ล้าง
7. เมนูซ้ายจัดกลุ่มตามงาน ("สถานการณ์น้ำท่วม", "ข้อมูลโครงข่ายและแผนที่", "บริหารและรายงาน") แถบไอคอนเมื่อจอ < 1536px

## 4. หน้าประชาชน (มือถือ)
- หัวเว็บสูง 64px: ชื่อระบบ/หน่วยงาน (`h1` ต้องมองเห็นเสมอ) + ปุ่มสายด่วน (ไอคอน+เบอร์)
- แถบล่าง: จำนวนจุดแยกตามสถานะ + ปุ่ม "ดูรายการสายทาง"; รายการสายทางเป็น bottom sheet; รายละเอียดจุดเป็น bottom sheet (`max-h 92dvh`, safe-area)
- รายการเรียงจุดอันตรายก่อน การ์ดเดียว (`FloodCard`) ใช้ร่วมทุกขนาดจอ
- ห้ามมี scroll ซ้อน scroll ในรายละเอียดจุดบนมือถือ

## 5. รายการที่ e2e อ้างถึง (ห้ามเปลี่ยนโดยไม่แก้ test — R7)
**หน้าประชาชน (`smoke.spec.ts`):** `h1` ต้องมีคำว่า "ทางหลวง" · มี `.leaflet-container` · มี `title="ระบบจัดการข้อมูลหลังบ้าน Admin"` · ปุ่มชื่อ "ดูรายการสายทาง" (มือถือ; ต้องมีปุ่มเดียวที่ชื่อนี้) · ช่องค้นหา placeholder มี "ค้นหาสายทาง" · ข้อความ empty-state อยู่ใน `p` หรือ `h4` · ปุ่ม "ล้างตัวกรอง" · dialog ชื่อ "รายละเอียดจุดน้ำท่วม <ชื่อตอน>" · ในรายละเอียด: ข้อความสถานะ (เช่น "รถเล็กผ่านได้ ๑ ช่องทาง"), ชื่อทางเลี่ยงที่ผูก (ข้อความตรงตัว ในอีลิเมนต์เดียว), "อัปเดตล่าสุด:" (ต้องมีอีลิเมนต์เดียว) · ไม่มี scroll แนวนอนที่ 412px

**หน้าแอดมิน (`admin-menus.spec.ts`, `gis-import.spec.ts`):**
- มี `<aside>` (role complementary) **เพียงตัวเดียว** และปุ่มเมนูใน aside ต้องมี accessible name ตามชื่อเมนู: จัดการระบบ, รายการเหตุการณ์, รายการทางเลี่ยง, โครงข่ายสายทาง, โครงการผู้ว่าฯ, จัดการแผนที่, สไตล์เส้นทาง (ปุ่มเมนูมือถือเป็นข้อความ label ล้วน และต้องตรงตัวเมื่อค้นแบบ exact)
- หัวข้อประจำแต่ละเมนู (เมื่อเปิดเมนูแล้วต้องเห็นข้อความนี้): จัดการระบบ → "ข้อมูลทั่วไปและเบอร์โทรฉุกเฉิน" · จัดการแผนที่ → "จัดการแผนที่และรายงานเหตุการณ์" · รายการเหตุการณ์ → "ทะเบียนเหตุการณ์น้ำท่วม" · รายการทางเลี่ยง → "เส้นทางเลี่ยงทั้งหมด" · โครงข่ายสายทาง → "โครงข่ายสายทาง" · สไตล์เส้นทาง → "สตูดิโอปรับแต่งสไตล์เส้น" · โครงการผู้ว่าฯ → "แผนงานโครงการแก้ไขปัญหาน้ำท่วม"
- หัวข้อ/ข้อความ: "ทะเบียนเหตุการณ์น้ำท่วม" (heading), "ปรับแนวถนนทางหลวง" (heading), "บันทึกข้อมูลระบบ", "เพิ่มเหตุการณ์", "วาดทางเลี่ยงใหม่บนแผนที่", "เลือกไฟล์โครงข่ายเส้นทางหลวง", "เพิ่มโครงการใหม่", "นำเข้าแนวเส้นเพื่อแก้รายละเอียดภายหลัง", "บันทึกเป็นฉบับร่าง (ยังไม่แสดงบนแผนที่ประชาชน)" (ตรงตัว), "ตรวจสอบโครงข่ายสำเร็จ", "พบเส้นทาง 1 เส้นในไฟล์"
- ตัวแก้ไขแนวถนน: ปุ่ม "แนวถนน" (exact), **ปุ่มเดียวชื่อ "เกาะแนวถนน"** (ห้ามให้ปุ่มอื่นมีคำนี้ในชื่อ), "คืนค่าแนวเดิม", "ส่งออก GeoJSON", "ส่งออก KML" · ตัวแก้ไขเปิดในโหมด "ตามถนน (OSRM)" เป็นค่าเริ่มต้น
- ฟอร์มจัดการแผนที่: input `aria-label` "พิกัดจุด A" / "พิกัดจุด B" (ต้องเจอเพียงอีลิเมนต์เดียวต่อชื่อ) · ปุ่ม exact "เส้นน้ำท่วม" และ "ทางเลี่ยง" · ปุ่ม "คำนวณเส้นเกาะถนน", "แตะจุดกลางเส้นเพื่อเพิ่มจุด", ปุ่มที่มี /เพิ่มจุดดัดเส้น/ (ต้องมีปุ่มเดียว), /คลิกถนนเพื่อดัด/ (สถานะกำลังรอ), "ล้างข้อมูลทั้งหมด", "ลบจุดดัดที่ 1" · กลุ่ม `aria-label="รายการจุดดัดเส้น"` · checkbox /บังคับตรงผ่านสามแยก\/สี่แยก/ · หมุดปลายทาง `.doh-draft-endpoint`
- ทะเบียนเหตุการณ์: label "ขอบเขตส่งออกเหตุการณ์", "รูปแบบส่งออกเหตุการณ์" · ทางเลี่ยง: "ขอบเขตส่งออกทางเลี่ยง", "รูปแบบส่งออกทางเลี่ยง" · "ไม่พบรายการเส้นทางเลี่ยง" · ปุ่ม /วาดทางเลี่ยงใหม่/ · ปุ่ม /แก้ไขสำนักงาน/, ข้อความ "หมุดของรายการนี้ปลดล็อกแล้ว"
- สไตล์เส้น: label "ความหนาเส้นเป็นพิกเซล", ข้อความ "เปิดเส้นขอบ (Stroke/Casing)"
- **Phase 5 E2E Selectors (`detour-navigation.spec.ts`):**
  - ป้ายหมุด 3 ระดับ Zoom บนแผนที่: `.doh-capsule-zoom-far`, `.doh-capsule-zoom-mid`, `.doh-capsule-zoom-near` พร้อมคลาสสี 5 สถานะ (`.doh-capsule-red`, `.doh-capsule-orange`, `.doh-capsule-amber`, `.doh-capsule-sky`, `.doh-capsule-emerald`, `.doh-capsule-slate`)
  - โครงสร้าง Popup มาตรฐานสูง: `.leaflet-popup-content-wrapper` ไร้กรอบซ้อนกรอบ หัวข้อรหัสสายทางและตอนควบคุมอยู่บรรทัดเดียวกัน ปุ่ม `.doh-detour-nav-btn` และ `.doh-detour-detail-btn`
  - ตารางโครงข่ายทางหลวง: ช่องค้นหา `ค้นหาหมายเลขทางหลวง หรือชื่อสายทาง...`, ตัวกรอง `ประเภททางหลวง`, `หมวดทางหลวง/หน่วยงาน`, `สถานะการแสดงผล`, คอลัมน์ตรึง (Sticky) `#`, `เปิด/ปิด`, `จัดการ`
  - จัดการทางเลี่ยง: การ์ดมือถือ `md:hidden`, แท็บทิศทาง `A ➔ B (ขาไป)` / `B ➔ A (ขากลับ)`, ฟิลด์ `Google Maps URL อนุมัติแล้ว (ขาไป A -> B)` และ `(ขากลับ B -> A)`

## 7. Phase 6 UPDATE-068 — หน้ารายการฝั่งประชาชน (มือถือ)
- รายการสายทาง Bottom Sheet 3 ระดับ: `peek` (ย่อ), `list` (รายการ), `full` (เต็มจอ) ผ่านปุ่มเปลี่ยนระดับ; เมื่อเลือกทางเลี่ยงจากรายการ ต้องซ่อนรายการขณะเปิดรายละเอียด และเมื่อกดปิดรายละเอียดจึงคืนรายการพร้อมตัวกรองเดิม.
- หัวข้อบนมือถือ "สถานการณ์ทางหลวง"; แท็บ ทั้งหมด/น้ำท่วม/ทางเลี่ยงพร้อมจำนวนจริง; ช่องค้นหา placeholder ต้องมี "ค้นหาสายทาง" สำหรับ e2e; ตัวกรองสายทางเดียวกันต้องใช้กับน้ำท่วมและทางเลี่ยง และรองรับชื่อสายทางชนบท ปน.
- รายละเอียดทางเลี่ยง: ชื่อยาวต้องขึ้นบรรทัดใหม่ได้, ปุ่มทิศทางที่ไม่ได้รับอนุญาตต้อง disabled, ไม่ตั้งค่า unknown เป็น `TWO_WAY`, รายละเอียดคำแนะนำใช้ข้อความเดิมจากแอดมินโดยแยกขั้นตอน/หมายเหตุ; ไม่แสดงระยะทาง/เวลาโดยเดา.
- ความปลอดภัย: ปุ่ม Google Maps ใช้ `resolveDetourGoogleMapsNavigation` ตามสิทธิ์และแหล่งลิงก์เดิม ห้ามตัด disclaimer สำคัญหรือให้ปุ่มนำทางแก่ทิศทางที่ไม่ได้ยืนยัน; รูปแบบรายละเอียด React และ Leaflet Popup ยังเป็นคนละ surface ตาม KI-006.
- E2E ใหม่: `tests/e2e/public-route-sheet.spec.ts` ตรวจกรองทางหลวง/ทางเลี่ยง, เปิดรายละเอียดไม่ซ้อน Sheet, ชื่อยาว, ปุ่ม reverse disabled, ย้อนกลับแล้วคงตัวกรอง.
